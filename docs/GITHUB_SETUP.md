# Putting this project on GitHub under your account

This walks through creating the repository, stamping your identity onto **every file**, and publishing a citable release. Commands assume macOS or Linux; on Windows use Git Bash or WSL.

Throughout, replace `YOUR-GITHUB-USERNAME` with your actual username.

---

## Step 1 — Install git and sign in

```bash
git --version          # if missing: https://git-scm.com/downloads
```

Create the account at <https://github.com/signup> if you do not have one. Use an email you will keep; an institutional address is fine.

---

## Step 2 — Set your git identity

This is what appears as the author of every commit. Set it **before** your first commit, because rewriting it afterwards means rewriting history.

```bash
git config --global user.name  "Juby Mathew"
git config --global user.email "jubymathew@amaljyothi.ac.in"
git config --global init.defaultBranch main
git config --list | grep user      # confirm
```

If you prefer to keep your address private, enable *Settings → Emails → Keep my email addresses private* on GitHub and use the `username@users.noreply.github.com` address it gives you.

---

## Step 3 — Stamp your identity onto every file

The project ships with placeholders (`YOUR-GITHUB-USERNAME`, `YOUR-ZENODO-ID`, …). One script replaces them everywhere and adds a provenance header to every Python file.

```bash
# see what would change, without changing anything
python scripts/set_identity.py --github-user YOUR-GITHUB-USERNAME --check

# apply it
python scripts/set_identity.py --github-user YOUR-GITHUB-USERNAME
```

It updates `pyproject.toml`, `CITATION.cff`, `README.md` and the docs, and puts this at the top of each `.py` file, below the docstring:

```python
# --- project provenance (generated by scripts/set_identity.py) ---
# Project : derm-skintone-audit
# Repo    : https://github.com/YOUR-GITHUB-USERNAME/derm-skintone-audit
# Author  : Juby Mathew <jubymathew@amaljyothi.ac.in>
# ORCID   : 0000-0002-4660-5940
# Licence : MIT (see LICENSE)
# Paper   : Engineering Research Express, manuscript ERX-121504
# --- end provenance ---
```

Re-running is safe: headers are replaced, never stacked. The script never stamps itself, so its placeholders stay intact for the next person.

Other options:

```bash
python scripts/set_identity.py \
  --github-user YOUR-GITHUB-USERNAME \
  --repo derm-skintone-audit \
  --author "Juby Mathew" \
  --email jubymathew@amaljyothi.ac.in \
  --orcid 0000-0002-4660-5940 \
  --zenodo 1234567
```

Confirm nothing was missed:

```bash
grep -rn "YOUR-GITHUB-USERNAME\|YOUR-ZENODO-ID" . --exclude-dir=.git
```

The only expected hit is `scripts/set_identity.py` itself.

## Step 4 — Create the local repository

```bash
cd derm-skintone-audit
git init
git add .
git status            # read this list before committing
```

**Check `git status` carefully.** `.gitignore` already excludes `data/`, images, checkpoints and `.env`, but look anyway: once something is pushed, assume it is public forever, even if you delete it later.

```bash
git commit -m "Initial release: audit and pipeline for skin-tone bias in dermatology datasets"
```

## Step 5 — Create the repository on GitHub

On <https://github.com/new>:

- **Repository name**: `derm-skintone-audit`
- **Description**: Auditing and correcting skin-tone bias in dermatology image-recognition datasets (ERX-121504)
- **Public** — the paper's data availability statement promises a public release
- Add **no** README, .gitignore or licence; this project already has them

---

## Step 6 — Connect and push

```bash
git remote add origin https://github.com/YOUR-GITHUB-USERNAME/derm-skintone-audit.git
git branch -M main
git push -u origin main
```

When git asks for a password it wants a **personal access token**, not your account password:

1. <https://github.com/settings/tokens> → *Generate new token (classic)*
2. Note: `derm-skintone-audit push`; Expiration: 90 days; Scope: **repo**
3. Copy the token (it is shown once) and paste it as the password

To avoid retyping it:

```bash
git config --global credential.helper store      # Linux
git config --global credential.helper osxkeychain  # macOS
```

## Step 7 — Confirm the repository presents correctly

On the repository page, check that:

- The README renders and its links work.
- The sidebar shows **MIT licence**.
- **Cite this repository** appears (GitHub reads `CITATION.cff`).
- The **tests** badge passes under the *Actions* tab. The workflow in `.github/workflows/ci.yml` runs the suite on Python 3.10–3.12 and re-checks that the projection still reproduces the published value.

Add topics via the gear icon beside *About*: `dermatology`, `fairness`, `medical-imaging`, `skin-tone`, `reproducible-research`.

## Step 8 — Mint a DOI with Zenodo

The paper's data availability statement promises an archived DOI. A GitHub URL is not one; it can change or disappear.

1. Sign in to <https://zenodo.org> with GitHub.
2. *Settings → GitHub*, then flip the switch beside `derm-skintone-audit` **on**.
3. Back on GitHub: *Releases → Create a new release*.
   - Tag `v1.0.0`, title `v1.0.0 — ERX-121504 accepted version`
   - Describe what the release contains
   - **Publish release**
4. Zenodo archives it within a few minutes and issues a DOI.

Then write the DOI back into the project and push again:

```bash
python scripts/set_identity.py --github-user YOUR-GITHUB-USERNAME --zenodo 1234567
git add -A
git commit -m "Add Zenodo DOI to citation metadata"
git push
```

Use the **Concept DOI** (the one that always points at the newest version) in the manuscript.

## If something goes wrong

**Pushed a file you should not have.** Deleting it in a later commit is not enough; it stays in history. Use [`git filter-repo`](https://github.com/newren/git-filter-repo) to purge it, then force-push. If it was a credential, revoke it immediately — assume it is compromised.

**`error: failed to push some refs`.** The remote has commits you do not. Run `git pull --rebase origin main`, resolve any conflicts, then push.

**Wrong author on commits already made.** For the most recent commit: `git commit --amend --author="Juby Mathew <jubymathew@amaljyothi.ac.in>"`. For several, rewriting history is the only route — easier to fix the config and start a fresh repository if nothing is published yet.

**Repository is too large.** Check with `du -sh .git`. Usually a committed dataset or checkpoint. Confirm `.gitignore` covers it, then purge it from history.
